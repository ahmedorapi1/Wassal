# تقرير إصلاح واجهة مناطق الخدمة المعروضة فعليًا

## المسار والمكوّنات الفعلية

- الرابط الفعلي لتطبيق الإدارة هو `http://localhost:3001/`.
- زر **مناطق الخدمة** لا يغيّر عنوان URL؛ بل يغيّر حالة التبويب إلى
  `zones` داخل `AdminApp`.
- شجرة العرض الفعلية:
  - `apps/admin-web/app/page.tsx` → `AdminPage`
  - `apps/admin-web/app/admin-app.tsx` → `AdminApp`
  - `tab === 'zones'` → `ZonesView`
  - نموذج الإنشاء/التعديل → `ZoneEditor`
  - خريطة العرض والاختيار الوحيدة → `ServiceZoneMap` في
    `apps/admin-web/app/service-zone-map.tsx`
- لم يُعثر على route قديم، أو مكوّن بديل للموبايل/سطح المكتب، أو feature flag
  يعرض واجهة أخرى لمناطق الخدمة. المشكلة كانت في المكوّن المستخدم فعليًا، مع
  احتمال ظهور build قديم إذا ظلت عملية Next السابقة تعمل.

## السبب الجذري

1. كانت بطاقة المنطقة تعرض إجراءات العرض والتعديل والتفعيل/الإيقاف فقط، ولم
   يكن هناك إجراء حذف في `ZonesView`.
2. لم يكن الـ API يوفّر endpoint لحذف منطقة خدمة، ولذلك لم تكن الواجهة تستطيع
   تنفيذ حذف آمن حتى لو أضيف زر فقط.
3. صور بلاطات OpenStreetMap كانت تحصل على `inset: 0` مع قيم `left/top`
   محسوبة داخل واجهة RTL. أصبح لكل صورة `left + right + width` معًا، وفي RTL
   تجاهل المتصفح `left` وتكدست أعمدة البلاطات ناحية اليمين، بينما ظلت الدائرة
   محسوبة على عرض الخريطة الكامل.
4. الخريطة كانت تبدأ بأبعاد fallback قبل القياس الحقيقي، ولم تكن إعادة القياس
   النهائية بعد فتح الـ dialog تفصل تحديث مصفوفة البلاطات عن fit المركز والدائرة.
5. حاوية الخريطة والـ dialog لم تكن تفرض `width/min-width/box-sizing` بصورة
   كافية، وكان ذلك يسمح بالقص أو بقياس غير دقيق داخل الحاويات المتحركة أو
   الضيقة.

## ما تغير

### واجهة الإدارة

- أضيفت الإجراءات المرئية لكل منطقة:
  - **عرض على الخريطة**
  - **تعديل**
  - **إيقاف/تفعيل**
  - **حذف**
- لكل إجراء رمز، و`title` عربي، واسم وصول `aria-label` يتضمن اسم المنطقة.
- أضيف مربع تأكيد الحذف بالنص:
  - العنوان: **حذف منطقة الخدمة**
  - الرسالة: **هل تريد حذف منطقة الخدمة نهائيًا؟ لا يمكن التراجع عن هذا
    الإجراء.**
  - الأزرار: **إلغاء** و**تأكيد الحذف**
- تعرض الواجهة رسالة رفض الحذف الآتية عند وجود مراجع:
  **لا يمكن حذف منطقة الخدمة لأنها مرتبطة بفروع أو طلبات أو قواعد تسعير.
  يمكنك إيقافها بدلًا من حذفها.**
- عند محاولة حذف منطقة فعّالة، تعرض الواجهة أيضًا خيار
  **إيقاف المنطقة بدلًا من حذفها**.
- بعد نجاح الحذف، تعيد الواجهة طلب قائمة المناطق.
- يظل التعديل PATCH على معرّف المنطقة نفسه؛ لا يُستدعى مسار الإنشاء ولا تُنشأ
  نسخة مكررة.

### الخريطة

- أصبحت الخريطة بعرض الحاوية الكامل، بارتفاع أدنى واضح، ومن دون overflow أفقي
  في الـ dialog.
- لا تُنشأ مصفوفة البلاطات قبل الحصول على قياس حقيقي من
  `getBoundingClientRect()`.
- أضيف قياس فوري، وقياس بعد إطارين متتاليين، وقياس نهائي بعد `420ms`، مع
  إعادة الجدولة عند كل `ResizeObserver` وعند تغيير حجم النافذة.
- أصبحت طبقتا البلاطات والـ overlays تستخدمان الأبعاد المقاسة نفسها.
- أزيل تعارض RTL بإجبار طبقات الخريطة على `direction: ltr` وإلغاء `inset`
  من صور البلاطات.
- يضمن مولد المصفوفة أن يبدأ أول عمود/صف قبل حافة viewport وينتهي آخر
  عمود/صف بعد الحافة المقابلة بلا فجوات.
- تستخدم إعادة القياس آخر نقطة وآخر نصف قطر من refs حية.
- تعاد ملاءمة zoom لإظهار دائرة التغطية كاملة بعد تغير أبعاد الحاوية.
- بقيت وظائف pan، zoom، اختيار النقطة، سحب العلامة، البحث بالإحداثيات، وتحديث
  نصف القطر الحي في المكوّن الفعلي نفسه.

### الحذف الآمن في الـ API

- أضيف:
  `DELETE /api/v1/admin/service-zones/:zoneId`
- الصلاحية: `super_admin` فقط، مثل بقية إدارة مناطق الخدمة الحالية.
- الحذف يتم داخل transaction، مع قفل سجل المنطقة أولًا.
- لا يسمح إلا بحذف منطقة `INACTIVE`.
- قبل الحذف تُفحص ذريًا المراجع التالية:
  - فروع التجار التي تقع داخل حدود المنطقة جغرافيًا
  - الطلبات
  - عروض الأسعار
  - قواعد التسعير
  - علاقات مناطق المندوبين
  - قيود حسابات المندوبين المرتبطة بطلبات المنطقة
  - سطور التسوية المرتبطة بهذه القيود
  - سجلات التدقيق/التاريخ
  - الإشعارات المرتبطة بالمنطقة
- لا يوجد cascade delete.
- بعد نجاح الحذف يضاف سجل تدقيق append-only باسم
  `service_zone.deleted`.

## قبل وبعد

| الجانب            | قبل                              | بعد                                   |
| ----------------- | -------------------------------- | ------------------------------------- |
| بطاقة المنطقة     | عرض، تعديل، تفعيل/إيقاف          | الإجراءات الأربعة ومنها الحذف         |
| الحذف             | لا يوجد UI أو API                | تأكيد صريح وحذف آمن ذري               |
| المنطقة المرتبطة  | لا يوجد مسار                     | رفض 409 بلا cascade مع اقتراح الإيقاف |
| قياس الخريطة      | قياس أولي قد يصبح قديمًا         | قياس فوري ومتأخر ومراقبة resize       |
| تغير المركز/النصف | احتمال إعادة ملاءمة بقيم البداية | آخر قيم حية ثم fit للدائرة            |
| العرض الضيق       | احتمال قص أفقي/ارتفاع غير كافٍ   | عرض كامل وارتفاع أدنى responsive      |

## التحقق

نجحت الفحوص التالية:

- TypeScript لتطبيق Admin Web.
- TypeScript للـ API.
- ESLint للملفات المتأثرة دون تحذيرات.
- 11 اختبار Admin Web مستهدفًا:
  - ظهور الإجراءات الأربعة وأسماء الوصول.
  - مربع تأكيد الحذف.
  - عرض رسالة رفض الحذف المرتبط.
  - فتح نموذج التعديل والخريطة الفعلية.
  - تغيير المركز ونصف القطر وحفظ نفس المنطقة من دون استدعاء الإنشاء.
  - ملاءمة الدائرة داخل viewport بحجم جهاز لوحي.
  - تغطية كل صفوف وأعمدة البلاطات المطلوبة بلا فجوات.
  - إعادة القياس من `960×500` إلى `640×420` عبر `ResizeObserver`.
  - منع عودة تعارض `inset` واتجاه RTL.
- 3 اختبارات تكاملية للـ API:
  - إدارة الدائرة والتغطية.
  - منع التكرار وحد المسار.
  - رفض مستخدم التاجر، نجاح حذف منطقة خاملة بلا مراجع، إنشاء سجل التدقيق،
    ورفض حذف منطقة مرتبطة.
- نجح build الإنتاجي لكل من API وAdmin Web.
- بعد التشغيل:
  - `http://127.0.0.1:3100/api/v1/health` أعاد HTTP 200.
  - `http://127.0.0.1:3001` أعاد HTTP 200.

## التحقق في المتصفح الفعلي

تم فتح `http://localhost:3001` في متصفح Codex وتسجيل الدخول بحساب الإدارة
المحلي، ثم نُفّذت الخطوات الآتية على الواجهة الفعلية:

1. فتح تبويب **مناطق الخدمة** والتأكد من ظهور الإجراءات الأربعة لكل المناطق.
2. فتح تعديل **منطقة دمياط التجريبية** ثم الخريطة:
   - ظهرت الخريطة بعرض الـ dialog.
   - ظهرت دائرة التغطية كاملة والعلامة داخلها من دون قص.
   - تم تغيير المركز من `31.410000, 31.825000` إلى
     `31.411000, 31.826000`.
   - تم تغيير نصف القطر من `25` إلى `26` كم.
   - تم الحفظ وإعادة الفتح، فظهرت القيم الجديدة.
   - بقي عدد المناطق `3` وبقي المعرّف نفسه
     `80000000-0000-4000-8000-000000000001`.
   - أُعيدت بيانات المنطقة التجريبية الأصلية بعد الاختبار.
3. أضيف fixture خامد بلا مراجع باسم
   **منطقة اختبار حذف الواجهة 25ea3fe8**:
   - ظهر في القائمة بحالة متوقفة.
   - ظهر مربع التأكيد بالنص المطلوب.
   - نجح الحذف من الواجهة، اختفى من القائمة، وأعاد GET للمعرّف HTTP 404.
4. جُرّب حذف **منطقة بورسعيد التجريبية** المرتبطة:
   - رُفض حذفها وهي فعّالة وظهر خيار الإيقاف البديل.
   - تم إيقافها مؤقتًا ثم أعيد الحذف.
   - ظهر نص رفض المراجع المطلوب، وبقيت المنطقة موجودة.
   - أُعيد تفعيلها بعد الاختبار.
5. في نهاية التحقق ظل Admin Web والـ API يعيدان HTTP 200.
6. بعد الإصلاح المؤكد بالصورة أُعيد فتح خريطة التعديل:
   - غطت البلاطات العرض الكامل من الحافة إلى الحافة بلا مساحة مسطحة.
   - بقيت العلامة والدائرة متطابقتين مع البلاطات.
   - ظهر الـ dialog كاملًا داخل viewport وظهر حقل نصف القطر كاملًا.
   - تم تغيير المركز إلى `31.265300, 32.301900` والنصف إلى `35` كم؛ أعيدت
     مصفوفة البلاطات وظهرت الدائرة كاملة بلا فراغ، ثم أُلغي النموذج دون حفظ.

تم التحقق البصري بسطح مكتب من الخريطة الفعلية في وضعي التعديل والعرض فقط.
واجهة المتصفح المتاحة لا توفّر أمر تغيير حجم viewport، لذلك لم أدّع تحققًا
بصريًا على جهاز لوحي؛ غُطي ذلك باختبار حساب الملاءمة عند viewport
`700×360`، واختبار component، وقواعد CSS responsive عند `max-width: 900px`.
