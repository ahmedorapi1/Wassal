# تقرير تنفيذ تحديثات عمليات إدارة WASSAL من 1 إلى 4

تاريخ التحقق النهائي: 29 يوليو 2026  
المنطقة الزمنية التشغيلية: `Africa/Cairo`

## النتيجة

نُفذت التحديثات الأربعة داخل نموذج WASSAL الحالي دون إنشاء نماذج طلبات أو
تسويات موازية. تعتمد كل عمليات التجميع والتصفية على `serviceZoneId` الثابت،
وتحافظ القواعد الجديدة على عروض الأسعار والطلبات والسجلات المالية التاريخية.

## التحديث 1 — قواعد التسعير

### النموذج النهائي

الحقول الظاهرة والمستخدمة:

- اسم قاعدة التسعير.
- منطقة الخدمة الإلزامية من المناطق الموجودة.
- المحافظة والمدينة وحالة المنطقة ونصف القطر وأقصى مسافة مسار كمعلومات مشتقة
  للقراءة فقط.
- السعر الأساسي.
- المسافة المشمولة في السعر الأساسي.
- سعر الكيلومتر الإضافي.
- ثلاث شرائح وزن اختيارية باستخدام النموذج الموجود
  `upToGrams + surchargeMinor`.
- إضافة قابل للكسر.
- إضافة الحقيبة الحرارية.
- نسبة المرتجع للقراءة فقط، والقيمة الافتراضية 70%.
- نوع عمولة المنصة وقيمتها: نسبة مئوية أو مبلغ ثابت.
- تاريخ بدء التطبيق.

الحقول التي أزيلت من واجهة الإدارة:

- المحافظة والمدينة كمدخلات يدوية.
- نوع المركبة؛ تُحفظ داخليًا `MOTORCYCLE`.
- الحد الأدنى المنفصل؛ السعر الأساسي هو الحد الأدنى.
- أقصى مسافة داخل التسعير؛ تُقرأ من منطقة الخدمة.
- إضافات حجم الطرد.
- الضريبة.
- الأولوية.
- سعر مرتجع يدوي.

تظل حقول التوافق القديمة في قاعدة البيانات بقيم ثابتة أو صفرية حتى لا تنكسر
الطلبات التاريخية أو مسارات المراحل السابقة.

### الصيغ

```text
المسافة الإضافية بالمتر = max(0, مسافة المسار - المسافة المشمولة)

إضافة المسافة =
roundHalfUp(المسافة الإضافية × سعر الكيلومتر / 1000)

سعر الرحلة =
السعر الأساسي
+ إضافة المسافة
+ إضافة الوزن
+ إضافة قابل للكسر
+ إضافة الحقيبة الحرارية
```

المرتجع:

```text
سعر المرتجع = roundHalfUp(سعر الرحلة الأصلي × 70%)
```

لا تدخل عمولة المنصة أو الضريبة في أساس حساب المرتجع. تُحفظ نسبة المرتجع
وقيمته المحسوبة داخل `breakdown` التاريخي للعرض ثم `pricingSnapshot` للطلب.
لا ينشئ مسار المرتجع عمولة ثانية.

### التفعيل والحذف والأرشفة

- يوجد قيد قاعدة بيانات جزئي فريد
  `PricingRule_one_active_rule_per_zone` يمنع وجود أكثر من قاعدة `ACTIVE`
  للمنطقة نفسها.
- عند تفعيل قاعدة جديدة، تُقفل منطقة الخدمة داخل معاملة، وتُوقف القاعدة
  السابقة وتُسجل العملية في التدقيق قبل تفعيل الجديدة.
- تفعيل إعداد مستقبلي لمنطقة متوقفة يتطلب تأكيدًا صريحًا في الواجهة.
- يمكن حذف قاعدة غير نشطة لم تستخدمها عروض أو طلبات.
- القاعدة المستخدمة تاريخيًا لا تُحذف؛ تتحول إلى `RETIRED` وتختفي من العرض
  الافتراضي مع إمكانية إظهار المؤرشف.
- حوار الحذف عربي وقابل للوصول ويعرض بوضوح أن الحذف لا يمكن التراجع عنه.
- يبقى سجل التدقيق كـ tombstone حتى بعد حذف قاعدة غير مستخدمة؛ لا توجد علاقة
  مفتاح أجنبي منه إلى القاعدة المحذوفة.

### API وقاعدة البيانات

- `GET /api/v1/admin/pricing-rules?includeArchived=true|false`
- `POST /api/v1/admin/pricing-rules`
- `POST /api/v1/admin/pricing-rules/:id/new-version`
- `POST /api/v1/admin/pricing-rules/:id/activate`
- `POST /api/v1/admin/pricing-rules/:id/deactivate`
- `POST /api/v1/admin/pricing-rules/:id/archive`
- `DELETE /api/v1/admin/pricing-rules/:id`
- حقل جديد: `PricingRule.returnTripPercentageBasisPoints` بقيمة افتراضية
  `7000` وقيد بين 0 و10000.
- الهجرة:
  `20260729193000_admin_operations_updates_1_to_4`.

## التحديث 2 — توثيق المناديب

### الحالات والعدادات

- `PENDING_REVIEW` ← تحت المراجعة.
- `APPROVED` ← معتمد.
- `CHANGES_REQUESTED` ← مطلوب تعديل.
- `SUSPENDED` ← موقوف.

تعرض الصفحة أربع بطاقات مباشرة بعدادات فعلية، وتبدأ بقائمة تحت المراجعة.
النقر على أي بطاقة يغيّر المرشح ويُحدث القائمة.

### القائمة والتفاصيل

المرشحات:

- الحالة.
- منطقة الخدمة.
- المدينة.
- تاريخ التقديم من/إلى.
- انتهاء مستند قبل تاريخ.
- الاسم أو الهاتف.

تعرض القائمة الاسم والهاتف والمدينة والمناطق المرتبطة وتاريخ التقديم وحالة
المستندات وآخر مراجع وتاريخ المراجعة. تستخدم القائمة ترقيمًا من 25 صفًا.

ملف المندوب يعرض:

- البيانات الشخصية المسموح بها.
- حالة الحساب والمدينة ومناطق التشغيل.
- الدراجة المسجلة.
- المستندات الحالية ونوع الملف والحجم والانتهاء وحالة المراجعة.
- فتحًا آمنًا للمستند عبر API مصرح به.
- أحدث 50 حدث تحقق من أصل أحدث 100 حدث محمل.
- سجل التدقيق.

الإجراءات:

- اعتماد مستند.
- رفض مستند بسبب.
- طلب استبدال مستند بسبب.
- اعتماد مندوب مكتمل.
- طلب تعديل بسبب.
- تعليق مندوب مع سبب.
- إعادة تفعيل مندوب صالح.

تُحدّث العدادات والقائمة بعد كل قرار. مسارات الملف والمستندات مقيدة بأدوار
`operations_admin` و`super_admin`.

### API

- `GET /api/v1/admin/courier-verification/summary`
- `GET /api/v1/admin/couriers` مع المرشحات الجديدة.
- `GET /api/v1/admin/couriers/:id`
- `POST /api/v1/admin/couriers/:id/request-changes`
- مسارات اعتماد/رفض/استبدال المستند وتعليق/إعادة تفعيل المندوب الموجودة
  أصبحت متاحة من مساحة العمل الجديدة.

لا توجد هجرة قاعدة بيانات لهذا التحديث.

## التحديث 3 — المالية والتسويات حسب المنطقة

### لوحة المناطق

تبدأ صفحة المالية ببطاقات مناطق الخدمة بدل خلط كل المناديب. تعرض كل بطاقة:

- عدد المناديب ذوي العضوية النشطة والحساب النشط وحالة التحقق `APPROVED`.
- عدد التسويات المفتوحة والمتأخرة.
- المتبقي للشركة.
- المحصل اليوم.
- المحصل خلال الشهر الحالي.
- آخر نشاط.

بعد فتح المنطقة، تظهر بطاقات الملخص وقائمة المناديب مع:

- المكتمل والمرتجع.
- قيمة الطلبات الإجمالية.
- عمولة المنصة المستحقة.
- المدفوع والمتبقي.
- تاريخ الاستحقاق وحالة التسوية.
- آخر دفعة وآخر نشاط.
- بحث بالاسم أو الهاتف، ومرشح حالة، وفترة نشاط، وترقيم من 25 صفًا.

تظل الأدوات المالية العامة الحالية متاحة من زر منفصل ولا تختلط بالعرض
التشغيلي الافتراضي.

### صيغة التجميع

مصدر الحقيقة هو نموذج التسويات الحالي:

```text
المستحق للمنطقة =
sum(مبالغ SettlementLine المرتبطة بطلب مصدره يحمل serviceZoneId)

المدفوع المؤكد للمنطقة =
sum(ExternalPaymentAllocation الفعال وغير المعكوس)
منسوبًا إلى مناطق خطوط الفترة نفسها

المتبقي للشركة = max(0, المستحق - المدفوع المؤكد)
```

إذا احتوت فترة واحدة على أكثر من منطقة، توزع الدفعة بنسبة الأرصدة الموجبة
لخطوط الطلبات، وتستخدم طريقة أكبر البواقي حتى يُنسب كل قرش مرة واحدة فقط.

- المحصل اليوم: الدفعات الفعالة داخل يوم القاهرة
  `[00:00 اليوم، 00:00 غدًا)`.
- المحصل هذا الشهر: من أول يوم في شهر القاهرة حتى بداية الغد.
- سجلات إثبات الدفع المعلقة لا تدخل الحساب؛ لا ينشأ
  `ExternalPaymentRecord` إلا بعد اعتمادها.
- السجلات المعكوسة لا تدخل الحساب.

### الصلاحيات والتدقيق

- `finance_admin` و`super_admin` فقط يمكنهما فتح مساحة المالية الجديدة.
- تحقق حي: `operations_admin` حصل على `403` لمسار المناطق المالية، بينما
  `finance_admin` حصل على `200`.
- فتح لوحة مالية لمنطقة يسجل `zone_finance.viewed`.
- إجراءات الدفع والتعديل والإغلاق تستمر عبر مسارات المرحلة الثالثة المدققة.

### API

- `GET /api/v1/admin/finance/zones`
- `GET /api/v1/admin/finance/zones/:serviceZoneId`

لا توجد هجرة أو محفظة موازية لهذا التحديث.

## التحديث 4 — الطلبات حسب المنطقة

### السلوك

تبدأ صفحة الطلبات ببطاقات مناطق الخدمة. تعرض كل بطاقة الحد الأدنى المطلوب:

- طلبات اليوم.
- الطلبات النشطة الآن.
- المكتملة اليوم.
- المرتجعة اليوم.

فتح البطاقة يقفل نطاق القائمة إلى `serviceZoneId` المخزن على الطلب. لا
يُستنتج النطاق من اسم مدينة حر. يوجد عرض اختياري لكل المناطق لدور
`super_admin`.

تظهر تسع مجموعات حالة ثابتة، حتى عندما يكون العدد صفرًا:

- جديدة.
- متاحة للمناديب.
- مقبولة.
- جارٍ الاستلام.
- قيد التوصيل.
- مكتملة.
- مرتجعة.
- ملغاة.
- متنازع عليها.

النقر على البطاقة يرسل `statusGroup` إلى API ويبقى النطاق في رابط الصفحة.

قائمة الطلبات تعرض:

- رقم الطلب وتاريخ الإنشاء.
- التاجر والفرع.
- عنوان الاستلام والتسليم.
- اسم المستلم وهاتفه المقنع.
- المندوب ووقت القبول.
- الحالة وآخر تحديث وعلامة الاعتراض أو الإرجاع.
- السعر والمسافة ومنطقة الخدمة.
- فتح تفاصيل الطلب الحالية وسجل حالاته.

المرشحات:

- الحالة أو مجموعة الحالة.
- التاجر.
- الفرع.
- المندوب.
- تاريخ الإنشاء.
- رقم الطلب.
- هاتف المستلم.

كل طلب داخل العرض المحدد يظل مقيدًا إلى `serviceZoneId`. تستخدم القائمة
ترقيمًا من 25 صفًا.

### API

- `GET /api/v1/admin/order-zones`
- `GET /api/v1/admin/order-zones/:serviceZoneId/summary`
- توسعة `GET /api/v1/admin/orders` بدعم:
  `serviceZoneId`, `statusGroup`, `courierId` وبقية المرشحات.

لا توجد هجرة لهذا التحديث لأن `DeliveryOrder.serviceZoneId` موجود ومفهرس.

## قيود معروفة مقصودة

1. قواعد التسعير القديمة التي لا تحمل `serviceZoneId` تُعرض كتاريخ قديم ولا
   يمكن تفعيلها مباشرة؛ يجب إنشاء نسخة جديدة مرتبطة بمنطقة.
2. تعديلات أو إعفاءات دفتر الأستاذ غير المرتبطة بطلب لا يمكن نسبها بأمان إلى
   منطقة، لذلك تبقى في الأدوات المالية العامة ولا تُوزع بالتخمين على المناطق.
3. لا تضيف هذه التحديثات ضريبة أو مركبات أخرى أو نموذج تسويات جديد؛ هذه أمور
   خارج نطاق MVP الحالي.
